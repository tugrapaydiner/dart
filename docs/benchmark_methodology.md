# Benchmark methodology

## Principles

1. **Exactness is a gate, not a metric.** Every benchmark row re-runs the
   exact-match check; a row that is not 1.000 exact is reported as a
   failure and the run exits non-zero (`benchmarks/run_bench.py`).
2. **Acceptance metrics are hardware-independent; wall-clock is not.**
   On the CPU reference setup, acceptance rate / accepted-tokens-per-round /
   accepted-tokens-per-diffusion-forward are meaningful; speedups are not,
   because draft and target cost ratios differ wildly from GPU reality.
   Report wall-clock claims only from GPU runs, with hardware stated.
3. **Fixed seeds everywhere.** Prompt generation, drafter initialization,
   and corruption draws all take explicit generators.
4. **Headline claims carry uncertainty.** The reconciliation ablation runs
   both arms with identical drafter weights over several prompt seeds and
   reports the improvement as mean ± sample std (plus the per-seed table in
   the artifact); a single-seed delta is not a claim. Where a number *is* a
   single run - e.g. the GPU wall-clock table, which is one pass per lane
   on one machine - the artifact says so and the run config is recorded so
   it can be repeated.
5. **Figures are artifacts, not illustrations.** Every figure under
   `docs/figures/` is generated by `scripts/make_figures.py` from committed
   result files or stated formulas (provenance table in
   `docs/figures/SOURCES.md`), so a figure can never disagree with the data
   it claims to show. Published competitor numbers carry citations and a
   last-verified date; re-verify them before any public posting.

## Metrics (docs/design.md §13.2)

System: tokens/sec, wall ms (per phase: draft vs verify), GPU peak / KV
bytes (logical vs physical for the v0 unpacked quantizer - see
`QuantizedKVCache.stats()`).

Verification: exact-match rate vs target greedy; acceptance rate by lane;
tokens committed per verify round; rejection position distribution (from
JSONL round traces); accepted tokens per diffusion forward (the
reconciliation ablation headline).

## Required comparisons (design.md §13.3)

`benchmarks/run_bench.py` produces: target_only (ground truth), ngram,
ar_draft, compressed_kv int8/int4, sparse_kv, diffusion_discard,
diffusion_reconcile, mtp_untrained. The reconciliation claim compares the
two diffusion rows on accepted-tokens-per-diffusion-forward at equal
canvas/step budgets; `scripts/train_drafter.py` reports before/after
acceptance for the trained drafter.

## Honest-reporting rules (design.md §14)

Never claim "always faster" or "quality unchanged" - claim exact-match
rate (measured), acceptance/throughput on named workloads, and where the
approach fails (docs/failure_cases.md). Untrained drafters are labelled
`_untrained`; their numbers exist to validate machinery, not to impress.
